# CZL Mail 笔记模块：第一版功能需求与实现方案

日期：2026-10-19
状态：第一版需求与实现记录；测试版已构建，实际完成项与限制见下节。用户明确要求：轻量 Markdown 管理、自动附件、MCP 接入、模块默认开启且可在设置独立关闭、多设备本地与远端版本对比及自动拉取；侧栏「AI 助手」固定在底部、位于设置上方。其他默认值为本方案建议，可在实施前调整。

## 实施状态（2026-10-19）

当前已实现并构建隔离 macOS 测试版；本节为实际状态，后续章节保留目标设计，不代表每项均已完成。

- 本地原文采用独立 FULL/WAL SQLite 持久化，导出时生成普通 Markdown 文件；没有实现持续物化的本地 `.md` 镜像或 FTS 索引，当前全文检索使用本地原文匹配。
- 已接入默认开启的模块设置、独立 MCP 读写权限、标准附件及 Obsidian 图片嵌入兼容、YAML 折叠属性、TOC、拖动分栏及右键菜单。
- 远端复用 JMAP FileNode 条件写，真实服务器已验证笔记创建上传；临时与持久化 blobId 不同，保存内容基线摘要防止误报冲突。批量每轮最多12项，持续推进。
- MCP 当前 `get_note_operation` 以 `vaultId/noteId` 查询状态，而不是方案目标的 operationId；正文更新使用 expectedRevision。附件当前按 relativePath 读取，不是 attachmentId。
- 已通过 MCP 完成 Markdown 与附件的批量迁移验证，本地与远端逐项回读并核对 SHA-256 一致。
- 固定使用个人账号的 Notes 根目录，界面直接显示子项；支持图片与 PDF 附件预览、代码块复制与编辑，正文右侧工具区采用可折叠卡片。
- 移动/重命名不检查正文链接、图片引用或其他笔记中的文件名，不自动改写任何正文；非空目录保留子项 ID 整棵移动。版本、同步冲突、目录循环、同名和回收站状态仍校验。非空目录回收站通过祖先标记保持整棵子树。
- CodeMirror 实时预览为本项目适配层，未声称完整复刻 Obsidian；源码始终保留。网页与移动端不在本次交付内。
- 已执行 Go 回归、前端类型检查、新增文件 lint、翻译测试与实际 macOS 打包；全仓 lint 有既有49项错误，未为本需求批量改动无关模块。Windows包和真实多台物理设备交互尚未验收。

## 笔记交互与渲染调整（2026-10-20）

- 顶部只保留新建笔记、新建文件夹和重命名，图标按钮均有悬停提示；同步入口也有提示。导入、导出移至设置 → 笔记，执行前刷新未保存编辑。
- 顶部新建与目录树空白区右键固定在根目录创建，不受上次选择影响；文件夹右键仍在该目录创建子项。
- 目录树增加同库拖放，空白区可移回根目录；界面及后端拒绝自身/后代/跨库拖放。非空文件夹可整棵移动，子项 ID 与父链不变；不按正文内容阻止移动，也不自动改写引用。后端同时拒绝移动回收站祖先下的子项。
- 图片/PDF 附件在正文区预览，返回时保留原编辑器实例；正文图片单击可放大。本地与 HTTP(S) 远程图片默认加载，加载失败可重试，远程请求不发送 Referrer。预览附件期间不向隐藏笔记接收系统文件拖入。
- 阅读与实时预览共用 `components/notes/note-markdown.tsx` 和同一组排版类。实时预览以 CodeMirror 顶层区块为单位渲染，光标所在区块保留源码，源码模式不改写原文；表格、列表、引用、代码及图片不再各自另写渲染逻辑。
- 仅将 Markdown 内字面量 `<br>` 转成换行，BR 起始块保留后续正文，不开放任意 HTML；先完整转换全局引用和脚注，再按 HAST 源位置筛出实时区块。脚注区只渲染一次，跨视口跳转先挂载源位置，再等异步布局稳定定位。
- 实时预览不将整段正文设为 atomic range，Backspace/Delete 按字符处理；React widget 更新复用 DOM，不因前面修改导致图片反复挂载。
- 已通过本机 28 项笔记回归、15 项 i18n 回归、笔记相关 lint、前端类型检查与生产静态构建，以及 Go 笔记/MCP 桥回归。真实隔离 Chromium 已验证表格、180段长文脚注正跳/回跳、源码不变和无浏览器异常；Windows 隔离程序已直接 Go 编译通过。macOS 包由正式发布 CI 验证。
- 回归入口：前端 `pnpm test:notes` 与 `pnpm test:notes-browser`（使用系统 Chromium，可设 `CHROME_BIN`）；Go 为 `go test ./internal/notes ./internal/mcpbridge`。Wails 绑定不提交，新检出须先 `wails generate module` 再做前端类型检查；CI 平台构建会生成绑定。
- 本机 Go1.27 与已安装 Wails CLI 的旧资源分析依赖不兼容；本次以前端构建后 `go build -tags desktop,production` 生成隔离 exe 验证，未修改全局 CLI 或项目依赖。

## 编辑体验、时间与日记（2026-10-22）

- 实时预览改为每个文档版本只解析一次（`lib/notes/parse-note.ts`，unified + remark-gfm，等同 react-markdown 的 skipHtml 与 URL 清洗），各区块只切自己那段 HAST。区块组件以「本区块源码」为键比较，输入时其他区块的 React 根、图片与高度原样保留；含脚注或引用式定义的文档以全文为键，仍整体更新。CodeMirror 的 `estimatedHeight` 用量过的高度，长文滚动条不跳。
- 渲染元素带 `data-note-from/to` 源码偏移：点击渲染区块时按点击处文字把光标放进源码对应位置（`caretOffset` 按序匹配字符、跳过 Markdown 记号），任务框在实时预览与阅读模式都能直接勾选并改写 `[ ]`/`[x]`。区块被复用时偏移可能过期，事件处理一律用 `posAtDOM` 现算差值。
- 实时预览的源码标题按渲染字号显示，进入区块编辑时不跳动；切换实时预览/源码用 Compartment 重配，不重建编辑器，撤销与滚动保留。快捷键：Mod-B/I/E/K、Mod-Shift-X、Tab 缩进。
- 新建笔记不再弹窗：直接建「未命名」（`Edit.unique` 由后端加序号），打开后聚焦标题栏改名。标题栏显示所在目录、可直接改名、同步状态（冲突时是打开对比的按钮），对比与移入回收站收进「更多」菜单。重新打开模块时恢复上次打开的笔记。
- 搜索结果按修改时间倒序，带所在目录与命中片段（后端 `Entry.path`/`Entry.snippet`，只出现在返回值里，不落库）。
- 创建与修改时间：`Entry.created` 本地新建时记录，同步来的笔记取服务端 FileNode 的 `created`，旧数据在下次同步时补齐；拉取远端版本时修改时间取服务端 `modified`（只用于显示，不参与同步判断）。正文 front matter 里的 `created`/`date` 优先显示，保留从 Obsidian 迁移前的原始时间。正文右侧「信息」卡片显示创建、修改与字数。
- 日记：笔记顶栏「今日日记」打开当天日记，没有就建。目录与文件名用 Obsidian 日期写法（`YYYY MM DD dddd ddd HH mm`，`[...]` 原样），默认 `日记/YYYY/MM` + `YYYY-MM-DD-dddd`；模板是库内任一笔记的路径，支持 `{{date}}`、`{{time}}`、`{{title}}`、`{{date:格式}}`，留空用内置模板。已存在的日记原样打开，不会被模板覆盖。设置在 设置 → 笔记，随 `ai-settings.json` 跨设备同步。

## 1. 产品目标与范围

在 CZL Mail 内增加独立「笔记」模块，以普通 Markdown 文件和相对路径附件为数据格式，以现有文件存储为远端载体。提供接近 Obsidian 基础使用方式的目录树、编辑、自动附件、离线保存、后台同步和全文搜索，不实现其知识图谱体系。

第一版交付桌面端，沿用项目的 macOS / Windows 打包目标；不新增 Web 服务、独立登录或同步服务器。移动端、网页端笔记不在本次范围。

### 1.1 第一版必须有

| 领域 | 第一版要求 |
| --- | --- |
| 模块开关 | 默认开启，设置内独立关闭，后端与 MCP 同时生效 |
| 笔记库 | 固定使用个人账号下的 Notes 目录，自动创建或复用；目录树不展示根节点 |
| 目录管理 | 文件夹与笔记的新建、重命名、移动、排序、软删除和恢复 |
| Markdown | 实时预览编辑、源码模式、只读预览、撤销重做、文内查找 |
| 自动附件 | 粘贴截图、拖入图片和文件、自动落盘、插入普通相对链接 |
| 保存与同步 | 本地优先，持久化待同步队列，重启续传，明确同步状态，冲突不覆盖 |
| 搜索 | 标题、路径、正文检索，中文短词可查，显示命中摘要 |
| 导入导出 | 本地 Markdown 文件夹导入，保留层级及附件；完整笔记库导出 |
| MCP | 笔记查询、读取、新建、更新、目录操作、软删除恢复和附件访问 |
| 基础体验 | 中英界面、深浅主题、键盘操作、切换模块保留编辑位置 |

### 1.2 明确不做

- 双链、反向链接面板、关系图谱、标签数据库、插件市场、脚本执行。
- 多人实时协作、CRDT、自动三方合并、逐字同步。
- 公开分享链接、发布站点、内置 AI 改写和向量检索；MCP 已提供外部 AI 使用入口。
- PDF / Office 全文提取、OCR、附件正文搜索、附件自动清理。
- Obsidian 插件、画布、Dataview、特殊嵌入语法的完整兼容。
- 任意本地目录实时双向监听、外部编辑器热同步。
- 跨账号移动和共享账号可写笔记库。第一版只处理有明确读写权限的个人库。

## 2. 模块开关与生命周期

### 2.1 设置项

在「设置 → 通用」增加独立「笔记」设置页，关闭后仍能打开此页重新启用。

| 设置 | 建议默认值 | 作用域 |
| --- | --- | --- |
| 启用笔记 | true，缺失记录也视为 true | 当前设备、当前登录配置 |
| 笔记库目录 | 首次使用选择或创建 Notes | 按账号记录，本机保存映射 |
| 新附件位置 | 当前笔记目录下 assets/ | 按库 |
| MCP 读取笔记 | true，但受 MCP 总开关约束 | 本机 |
| MCP 写入笔记 | false，需用户主动允许 | 本机 |

启用开关不加入现有跨设备设置同步列表，避免在一台电脑关闭影响另一台。默认开启不等于首次启动就扫描整个网盘：用户第一次打开笔记时配置根目录，再启动笔记内容同步和索引。账号不支持文件能力时展示不可用说明，不影响其他模块。

### 2.2 关闭时的行为

1. 刷新当前编辑缓冲并确认本地持久化成功；失败则不完成关闭，展示原因。
2. 隐藏模块入口，拦截导航、快捷键及笔记 API；当前位于笔记时切回邮件。
3. 停止笔记正文预取、专属索引任务及待同步队列调度。已发出的网络请求可能完成，不承诺撤销；记录结果后停止后续步骤。
4. 保留本地草稿、待同步任务、远端文件、附件和回收站，不自动清空或删除。
5. 笔记 MCP 工具不再发布；旧客户端缓存的工具调用也必须经后端开关校验并拒绝。
6. 再次启用先核对远端变化，再恢复队列，不能将旧草稿直接覆盖远端。

普通模块切换继续沿用常驻挂载、隐藏不卸载的规则。显式关闭模块属于生命周期结束：完成安全落盘后可卸载笔记编辑器、释放内存和订阅。

### 2.3 权限边界

这是功能开关，不是文件加密或隐藏权限。笔记以普通文件存在，关闭后仍可在通用文件模块查看；现有通用 MCP list_files / read_file 的既有权限不因此改变。设置文案明确说明这一点。MCP 笔记读写权限只约束新增笔记工具，不宣称能隔离底层文件访问。

## 3. 界面与编辑行为

### 3.1 布局

- 左侧全局侧栏分为顶部业务导航与底部固定区：顶部是邮件、日历、通讯录、文件、笔记；底部从上到下为「AI 助手」「设置」。AI 助手按配置 / 集成入口定位，不与顶部业务模块混排，窗口高度变化也保持底部锚定。
- 原 AI 助手页面内容与访问能力保留，只调整入口位置；不因移动而新增一套设置页。快捷键映射与视觉顺序解耦，保留已有组合含义，为笔记分配未占用组合；关闭笔记不会让其他快捷键重新编号。底部区域支持键盘焦点和无障碍标签。
- 笔记内部左侧为可调整宽度的目录树，包含账号切换、搜索、新建按钮；隐藏 .md 扩展名但不改真实文件名。
- 右侧为面包屑、文件名和编辑区；状态放在现有工具行，不额外堆状态条。
- 首次进入展示选择已有目录 / 创建笔记库，不自动修改已有同名目录。
- 保留最后打开笔记、光标和滚动位置；第一版单编辑页，不做多标签页系统。
- 目录树按需展开加载；最近使用与收藏只存本机，可作为次优先级体验项。

### 3.2 Markdown 支持

支持标题、强调、删除线、普通链接、图片、引用、有序无序列表、任务列表、分隔线、行内代码、围栏代码块和 GFM 表格。默认实时预览，当前编辑区域显示必要标记；源码模式始终可切换，复杂表格可退回源码编辑，阅读模式正确展示。

- 文档源为 Markdown 字符串，不以富文本 JSON 或 HTML 作为权威数据。
- 标题栏对应文件名；正文首个一级标题不强制与文件名同步，避免无意改动原笔记。
- 未支持的 front matter、特殊语法按原文保留，不因切换模式重写整篇格式。
- 代码块支持复制；任务勾选直接更新 Markdown；附件点击使用受控本地文件打开流程。
- 中文输入法组合输入期间不做破坏性装饰重排；保存以组合输入完成后的有效文本为准。
- 原始 HTML 不执行脚本；预览输出清洗，拒绝 javascript: 等危险协议。
- 远程图片默认不自动加载，用户可选择加载，防止打开笔记即产生外部请求。

## 4. 文件格式与自动附件

### 4.1 推荐布局

```text
Notes/
  CZL/
    英国公司/
      HMRC 参考税号.md
      公司资料.md
      assets/
        截图-<随机ID>.png
        公司证书-<随机ID>.pdf
  .czl-trash/
```

图片写入 `![描述](assets/截图-ID.png)`，其他文件写入 `[公司证书.pdf](assets/公司证书-ID.pdf)`。实际链接由工具函数处理空格、中文、括号和 URL 编码，不能靠字符串拼接。正文不存服务器域名、blobId、认证 URL 或 base64 图片。

新附件支持选择统一 attachments/ 或当前目录 assets/；既有导入库保持原位置，不批量搬迁。两个位置策略都写普通相对路径。

### 4.2 插入流程

1. 用户粘贴图片、拖入文件或通过文件选择器添加附件。
2. Go 校验大小、类型和库内路径，复制至受控暂存区；普通 Markdown 粘贴仍按文本处理。
3. 附件在本机完成持久化后，返回 attachmentId 和相对路径。
4. 在当前光标位置插入链接，并保存正文；多文件保持操作顺序。
5. 后台先同步附件，再同步首次引用该附件的正文版本。
6. 失败时保留本地附件及待同步任务，显示重试入口，不出现看似成功却找不到文件的链接。

附件名加入随机 ID，避免覆盖同名文件；不改变用户原件。单文件上限取客户端配置与服务器上限的较小值。第一版不自动压缩图片，不下载远程 URL 为附件，不自动删除已无引用的附件。

粘贴 / 拖入操作须可恢复：附件落盘成功但链接尚未插入时，仅留下可识别的暂存记录，不丢原文件；重启后可恢复或提示处理，不静默将其当作已上传成功。

### 4.3 重命名、移动与引用

- 笔记身份使用本地稳定 ID，远端 FileNode ID 为映射，不能以路径充当唯一身份。
- 单独重命名 .md 不移动附件。跨目录移动时重算该笔记的相对链接，附件默认仍留原处，避免误移动共享附件。
- 文件夹移动保留子树结构，同时重算跨边界的标准 Markdown 引用。
- 针对标准行内 / 引用式 Markdown 链接建立内部引用索引；移动或改名时修复库内其他笔记指向目标的链接。它只是完整性维护，不提供双链产品功能。
- 用解析器定位并做局部文本修改，不用全局正则替换，不重新格式化全文。
- 同步未完成、依赖文档未下载或存在脏编辑缓冲时，受影响的批量移动先阻止并说明；不得拿旧缓存覆写编辑中的文档。
- [[wiki]]、特殊 HTML、库外路径等不承诺自动改写；导入扫描时提示兼容性，保留原文。不能把未知引用标记成「已修复」。
- 跨文件修改不是远端原子事务；用持久化操作日志逐项提交、记录进度并在失败后恢复，界面显示整理未完成。

## 5. 本地保存、同步与冲突

### 5.1 本地优先

建议编辑停止约 500ms 后提交保存；切换笔记、切换账号、关闭模块及正常退出时主动 flush。异常断电仍可能丢失尚未提交的极短输入窗口，不宣称零丢字。按 Ctrl/Cmd+S 立即落盘，不代表已经上传远端。

状态区分：保存中、本地已保存 / 待同步、同步中、已同步、同步失败、存在冲突、未下载不可离线打开。不能把「保存到本地」显示成「已同步」。

### 5.2 推荐本地数据组织

普通 .md 和附件作为可导出的文件表示；SQLite 保存版本、队列、映射、索引和可重放的保存日志。

建议在现有应用数据目录下使用 `notes/<serverKey>/<accountKey>/<vaultId>/`，隔离不同服务器和账号。实际路径用项目现有目录函数生成，不硬编码设备路径。

保存采用可恢复日志：先在 SQLite 事务内写入正文版本与落盘任务，再用临时文件加原子替换写入 .md，完成后标记文件已物化。界面只在所需步骤成功后显示本地已保存；启动时重放未完成落盘任务。附件采用暂存文件和持久化元数据，并在引用它的正文提交前确保文件可恢复。

外部直接修改托管目录不属于第一版支持入口；若启动检查发现文件与已记录摘要不符，保留异常文件并提示恢复，不擅自覆盖。用户通过导出获得可自由编辑的普通文件库。

建议新增表：

| 表 | 关键内容 |
| --- | --- |
| note_vaults | 本地库 ID、服务器及账号、根 FileNode ID、本地目录、初始化状态 |
| notes | 本地 noteId、远端 ID、相对路径、baseBlobId、localRevision、摘要、同步状态 |
| note_revisions | 未完成落盘的正文、版本与恢复状态；成功物化后按保留策略收敛 |
| note_attachments | attachmentId、文件摘要、相对路径、远端映射、上传状态 |
| note_operations | operationId、幂等键、依赖、期望版本、重试次数、结果与错误 |
| note_links | 标准本地链接的来源、目标与定位信息，可重建 |
| note_trash | 原位置、删除时间、恢复映射 |
| notes_fts | 标题、路径与正文检索索引，可重建 |

不复用或替换现有 file_nodes 作为本地编辑稿：file_nodes 继续反映远端已确认状态；笔记本地变更由覆盖层叠加，避免普通同步把离线草稿清掉。

### 5.3 远端协议与写入

第一版优先复用项目现有 JMAP FileNode；Stalwart 官方文件存储支持 JMAP 与 WebDAV，两者不是必须同时实现的两套后端。当前代码已有 FileNode 缓存、增量同步、blob 上传和通用文件界面。

现有 SetPIM 为在线写入、成功后刷新元数据，不提供笔记所需的持久化离线队列。新增 notes service / worker，在它下面复用传输和元数据基础设施；不直接把现有上传按钮改成自动保存。

队列按账号串行处理元数据写入，同一笔记合并尚未开始的连续保存版本；依赖附件、目录创建和前序重命名的任务必须等待依赖完成。上传过程中产生更新时，已上传快照和当前草稿分开记录，旧请求成功不能把新草稿误标为已同步。

初次绑定后先加载元数据，再按受限并发下载库内 .md 建立全文索引；附件按需下载，新建及已缓存附件离线可用。界面显示笔记下载与索引进度；首次下载未完成时不声称全库可离线使用或全文结果完整。重复打开不能重新全量下载。

### 5.4 并发保护是上线前置条件

本地 UI 与 MCP 使用同一 notes service、同一每笔记锁与 localRevision 乐观锁。UI 定期持久化缓冲，MCP 更新前协调活动编辑器完成 flush；无法安全 flush 时返回 note_busy。MCP 写入成功后发送版本事件，前端不得用尚未处理的旧缓冲再次自动保存。

远端更新使用「读取远端对象及 state → 比较 baseBlobId → 携带 ifInState 更新 FileNode」的流程。JMAP 的 state 是账号对象类型级别的状态，不是单文件版本；收到 stateMismatch 后重新读取并比较目标内容，不能直接盲重试。与内容无关的其他文件变化可在重新校验后有限重试。

标准 JMAP 定义了 ifInState，但当前部署的 FileNode 是否正确支持、旧 blob 能否可靠读取、错误返回如何表现，必须在获授权的测试环境验证。验证前不宣称已有多端防覆盖能力。若无法提供服务端条件写，不降级为「读一下再无条件写」；保留本地编辑与待同步状态，阻止危险覆盖，另行设计可验证的适配方案。

冲突规则：

- 远端变化且本地干净：下载新版本，原子替换并刷新编辑器。
- 本地和远端均变化：保留当前本地版本与远端版本，产生带设备短码和时间的冲突副本，等待用户处理；不静默合并。
- 远端已删除且本地有修改：保留为可恢复笔记，不重新创建原对象掩盖删除事实。
- 上传已成功但响应丢失：operationId 用于本机去重，重连后对照远端 ID / 摘要核实；不能声称本机幂等键可让服务器天然去重。
- 新建结果不确定且不能唯一识别远端对象：标记待核对，不盲目创建重复文件。
- 断网、限流、权限不足、配额超限分别展示；可重试错误退避，非重试错误等待处理。

### 5.5 多设备对比、自动拉取与差异查看

同步必须是双向流程，而非只把本地文件上传。设备 A 在服务端提交成功后，在线且已开启笔记的设备 B 应自动发现远端变化、对比本地状态并拉取新版，不要求用户重新打开页面或手动下载。

#### 变化触发与补偿

- 优先复用现有 JMAP 状态通知及 FileNode 增量同步；收到相关变化后，笔记 worker 获取库内受影响节点。通知是刷新信号，不把通知到达视为正文已更新。
- 增加有抖动的周期性对账作为漏通知补偿，建议在线且桌面实例运行时约 60 秒检查一次；前台活跃库优先，退避与省电策略实施时确定。多个触发合并、同账号避免并发重复请求。
- 应用启动、网络恢复、系统唤醒、窗口回到前台、重新启用笔记时主动对账；保留手动「立即同步」入口。
- UI 切换到邮件等其他模块不暂停已配置笔记库的后台双向同步；只有关闭笔记、退出应用或断网才停止对应工作。设备离线或应用退出时不承诺实时拉取。
- 增量 state 失效时重新分页枚举远端并与本地映射核对；不得清空本地草稿。正文按 blobId 变化下载，不因修改时间变化反复下载全部内容。

#### 对比依据与决策

每篇记录共同基线 baseBlobId / 基线元数据、本地 localRevision / 内容摘要、最新远端 blobId / 元数据。时间仅用于展示，不用设备时钟或「时间较新者胜出」决定覆盖。远端路径、删除状态和正文分别比较；远端仅改名也需要更新目录。

| 本地相对基线 | 远端相对基线 | 处理 |
| --- | --- | --- |
| 未改 | 未改 | 不下载、不重写 |
| 未改 | 已改 | 自动下载校验后替换本地；更新索引、目录和打开的编辑器 |
| 已改 | 未改 | 保留草稿，完成条件校验后上传 |
| 已改 | 已改，但最终正文相同 | 核对路径及附件状态后收敛基线，不重复制造正文冲突 |
| 已改 | 已改，最终正文不同 | 保留本地和远端两份，标记冲突，不自动选一份覆盖 |
| 未改 | 已删除 / 移至回收站 | 更新本地状态；若当前打开则提示并退出可编辑状态 |
| 已改 | 已删除 / 移至回收站 | 保留本地可恢复版本，明确提示远端删除冲突 |

下载需绑定待拉取 blobId，并在本地提交前再次检查 localRevision 与远端目标版本。下载期间用户开始输入时，不得以先前的「本地干净」判断覆盖新输入；转入版本比对或冲突流程。下载失败保留旧可用版本，不标记已更新。

#### 打开的编辑器与附件

- 干净文档收到新版时，自动刷新正文、文件名、附件引用和索引，尽量保留光标与滚动位置，提示「已从其他设备更新」。
- 处于输入法组合输入、未落盘编辑或有本地待同步改动时先保护缓冲，再对比；不能重置编辑器直接替换。后台库更新通过版本事件传播，隐藏的编辑器重新展示时核对版本。
- 新版引用尚未缓存的附件按需下载，展示加载 / 重试状态；远端已引用但不存在的附件明确标示缺失。若 A 的附件仍未同步，不应先发布引用它的正文版本。

#### 本地与远端差异界面

笔记菜单提供「与远端版本对比」：在线读取服务端当前版本，显示本地保存状态、双方版本信息、正文行级差异及路径 / 删除状态；未保存输入先安全 flush，失败则不继续。离线时仅允许与最近缓存远端版本对比，并明确注明不是远端最新状态。

冲突页支持并排查看本地 / 远端，窄窗口可切统一差异视图；允许复制内容、保留双方、采用远端或将本地作为新版本提交。默认保留双方。用户选择完成冲突解决前保留恢复副本，不能先永久删除另一版本。选择采用远端时提示将替换本地正文；选择提交本地仍须针对刚读取的远端版本条件写，若再次变化重新提示冲突。第一版不实现自动合并，但可手动编辑结果再提交。

## 6. 删除、恢复、导入与导出

删除默认移动到库内保留目录 .czl-trash/，保持原子树和附件相对结构；记录原位置，文件名冲突时恢复到新名字。第一版不提供 MCP 永久删除，也不自动清空回收站。库内回收站是客户端约定，不假设服务器自带文件回收站。

单篇笔记删除不删除 assets/ 中的共享附件。恢复、删除与移动都用相同队列，离线可记录；不能直接调用现有递归 destroy 路径替代软删除。

导入在本地扫描后展示数量、大小、特殊语法和缺失附件摘要；保留 .md 原文、目录及附件，排除 .git、缓存等，明确哪些项目跳过。拒绝符号链接逃出导入根目录，不执行内容，不覆盖同名远端文件。分批处理并支持取消，重试不重复导入已确认项。

导出为用户选择的目录，包含当前本地最新笔记、已获取附件和相对目录结构，不要求联网。若附件未下载，选择联网补齐再导出，或明确输出缺失清单，不能将不完整结果报告为完整备份。导出不包含令牌、缓存数据库或账号凭据。

## 7. MCP 设计

### 7.1 注册与权限

沿用已有 MCP server / stdio bridge，不开第二个端口、不启动独立进程。`czlmail mcp` 仍只连接已运行实例；不可用立即返回 `2141 mcp_unavailable`，不得启动桌面窗口。

笔记模块默认开启不改变 MCP 总开关默认关闭的行为。工具有效权限为：MCP 总开关 ∩ 笔记模块开启 ∩ 笔记读取权限；写操作再要求笔记写入权限和账号实际写权限。使用独立笔记写开关，避免允许邮件修改就顺带获得笔记写权限。

关闭模块或调整读取权限时撤下相关工具；在 SDK 能力允许时发送 tools/list_changed，兼容不刷新清单的客户端提示重新连接。所有 handler 在执行及提交前再次检查当前权限，工具注解只用于提示，不能代替授权。设置变更应取消尚未提交的操作，已发送的远端请求按实际结果记账。

同步更新 AI 助手页工具清单、MCP server instructions 和中英文说明。笔记正文、文件名与附件内容是非可信数据，不能作为工具指令或授权来源。

### 7.2 第一版工具契约

统一使用 camelCase 参数。读取返回 revision；对既有对象的修改必须带 expectedRevision。vaultId 明确库边界，省略 accountId 时解析个人账号；错误账号 / 库 / noteId 组合必须拒绝。

| 工具 | 主要参数 | 行为 |
| --- | --- | --- |
| list_note_vaults | accountId? | 列出已配置库、初始化和同步状态，不自动创建 |
| list_notes | vaultId, folderId?, cursor?, limit?, includeTrash? | 分页列目录与笔记摘要 |
| search_notes | vaultId, query, folderId?, cursor?, limit? | 查标题、路径、正文；返回命中摘要和索引覆盖信息 |
| read_note | vaultId, noteId, offset?, limit? | 返回原始 Markdown、revision、路径、附件元数据及分页信息 |
| create_note | vaultId, parentId?, name, content, idempotencyKey | 创建 .md，返回本地 noteId、revision、operationId |
| update_note | vaultId, noteId, expectedRevision, content, idempotencyKey | 完整正文替换；不支持隐式覆盖新版本 |
| create_note_folder | vaultId, parentId?, name, idempotencyKey | 建目录，返回 folderId |
| move_note_item | vaultId, itemId, expectedRevision, parentId?, name?, idempotencyKey | 移动或改名；执行统一引用维护 |
| trash_note_item | vaultId, itemId, expectedRevision, idempotencyKey | 移至回收站；目录操作返回影响数量 |
| restore_note_item | vaultId, itemId, expectedRevision, idempotencyKey | 恢复；重名返回实际恢复位置 |
| add_note_attachment | vaultId, noteId, expectedRevision, name, source, idempotencyKey | 添加受控附件，返回 attachmentId / relativePath / Markdown 片段及新 revision，不擅自决定正文插入位置 |
| read_note_attachment | vaultId, noteId, attachmentId, offset?, limit? | 读文本附件或返回受限图片内容；其他格式仅返回元数据及不支持说明 |
| get_note_diff | vaultId, noteId, expectedRevision | 在线获取当前远端版本并返回差异、remoteVersion；离线仅返回缓存对比并标 stale |
| resolve_note_conflict | vaultId, noteId, expectedRevision, expectedRemoteVersion, strategy, content?, idempotencyKey | 明确选择保留双方 / 采用远端 / 提交本地或手动合并结果；提交时再次校验双方版本，保留恢复副本 |
| get_note_operation | vaultId, operationId | 查询本地接受、远端同步、失败或冲突结果 |

建议列表默认 50、最大 200；正文分段默认 12000 字符，上限 50000。offset / limit 以 Unicode 字符计，不按 UTF-8 字节切片；返回 nextOffset、完整长度和 truncated。分页期间 revision 变化应提示重新读取。搜索返回 indexedNotes / totalNotes 和 incomplete，避免把未索引误当作没有匹配。

工具读写看到的都是本地最新已持久化状态，而不是仅远端快照。写操作返回 `savedLocally: true`、syncStatus、revision 和 operationId；不能把队列入队报告为远端已同步。第一版不提供无版本保护的 append，追加内容应先读完整内容，再带 revision 更新。

### 7.3 附件工具输入与安全

第一版 source 只接受有大小上限的 base64 数据，或属于该账号的现有文件 / 邮件附件标识；服务端校验来源权限，流式复制到受控目录。跨工具取得的裸 blobId 不能跳过归属核验。建议 base64 原始文件上限 5 MiB，最终结合 MCP 消息限制实测。

不提供任意 localPath 读取、不下载任意 URL，不接收由模型随意指定的绝对目标路径。大型文件继续由 UI 导入；后续需要时再设计用户授权的暂存 token。图片返回限制大小和实际媒体类型；不把二进制文件伪装成文本输出。

读取附件必须确认附件确实属于该笔记引用集 / 授权库，不允许遍历路径跳到应用配置、其他账号或密钥目录。

### 7.4 错误与并发

错误采用项目数字码 + 英文机器消息，UI 再翻译成人话。建议语义包括 notes_disabled、notes_unavailable、note_busy、note_conflict、note_revision_mismatch、note_attachment_too_large、note_path_outside_vault、note_write_forbidden。具体数字码实施前查全仓分配，不在方案中占用未经核对的编号。

revision 覆盖正文、路径、附件与删除状态，目录有自己的版本。MCP 更新命中不一致时返回当前 revision 和重新读取建议，不自动覆盖。幂等键与请求内容摘要绑定；相同键不同请求报错，相同请求重试返回已有 operation 结果。

## 8. 技术选型与代码落点

### 8.1 前端

建议 CodeMirror 6 为编辑核心，Markdown 原文为状态源，通过 decorations / widgets 实现有限实时预览；阅读模式使用支持 GFM 的解析器并清洗输出。具体包版本在实施时核查并固定锁文件。

不直接把现有邮件 Tiptap 编辑器拿来存 Markdown：本模块优先保证原文保留，不以富文本往返转换为默认保存链路。CodeMirror 实时预览仍需要专门开发，不把安装依赖等同于具备 Obsidian 编辑体验。

建议落点：

- `desktop/frontend/components/notes/`：模块外壳、目录树、编辑器、搜索、回收站、状态组件。
- `desktop/frontend/components/settings/notes-section.tsx`：独立功能开关和笔记配置。
- `desktop/frontend/lib/notes/`：编辑器扩展、Markdown 路径与预览适配。
- 现有 `lib/api.ts`、`lib/app-bus.ts`、`components/app-shell.tsx`：模块类型、绑定调用、事件和导航集成。
- 沿用 Tailwind / Shadcn、LocaleProvider 与 t()，英文词典覆盖全部新文案；文件内容不翻译。

### 8.2 Go 与本地存储

- `desktop/internal/notes/`：领域服务、路径安全、保存日志、队列、引用维护和冲突处理；不依赖 Wails UI。
- `desktop/internal/store/`：按现有迁移方式加笔记表、设置键与检索接口。
- `desktop/internal/syncer/` / `jmapx/`：补充 FileNode 条件写、结果核实及所需能力适配。
- `desktop/api_notes.go`：薄 Wails 桥，不放同步业务；体积增长时按查询、编辑、附件拆文件。
- `desktop/mcp_tools_notes.go`：复用 notes service 的工具注册；按职责拆分，避免大文件。
- Wails 绑定通过生成更新，不手改 `wailsjs/`。

UI、MCP 和后台队列统一经过 notes service。可复用文件下载、上传、权限、危险文件打开策略，但不能依赖会弹原生文件选择框的 UI 方法来实现 MCP。

### 8.3 检索

复用现有 SQLite FTS5 技术，笔记使用独立索引。trigram 检索覆盖较长子串；一到两个 Unicode 字符走转义后的 LIKE 子串查询，确保中文短词能查正文。只在库内查询，限制结果数并分页，不暴露 FTS 表达式。首版不建向量服务。

### 8.4 安全与资源边界

所有路径标准化后验证位于库内；防御 `../`、绝对路径、符号链接逃逸、Windows 保留名与大小写冲突。跨平台导入时列出不合法文件名，用户确认映射后再导入，不能静默改名破坏链接。

预览通过受控资源处理器按内部标识读取附件，禁止开放任意本地路径。只允许安全图片格式内嵌，SVG / HTML 作为附件处理，不直接注入预览 DOM。MCP 读写、搜索和导入均设置体积、并发和超时限制；队列错误日志不输出正文与凭据。

## 9. 实施顺序与验收门槛

### 阶段 A：能力与数据安全底座

确认实际服务器 FileNode 能力、条件更新、状态变更、删除、配额与权限行为；用本地假端点构建可重复回归。新增设置、表结构、保存日志、队列与恢复流程。条件写验证未通过，不进入正式多端写入交付。

### 阶段 B：本地笔记闭环

模块开关、目录、创建编辑、源码及阅读模式、本地保存、图片与文件插入、搜索。先保证离线可用和原文不损坏，再打磨实时预览装饰。

### 阶段 C：同步与文件操作

初次下载、状态展示、附件依赖、断点恢复、冲突副本、软删除恢复、移动引用维护、导入导出。与现有文件模块交叉操作验证。

### 阶段 D：MCP 与交付

注册工具、独立权限、revision、幂等和 operation 查询；验证 UI 与 MCP 并发；更新工具清单及文档，按既有流程完成静态检查、桌面打包与真实交互验收。

### 必须通过的验收用例

1. 新旧用户均默认开启；主动关闭后重启仍关闭，设置页始终可重新开启。
2. 关闭前草稿落盘，退出入口、快捷键、后端 API 和缓存 MCP 调用都被拦截；重新开启数据完整。
3. 关闭不删除云端或本地文件、不清队列、不停止其他模块文件元数据同步。
4. 断网创建笔记、粘贴截图、重启后继续编辑；联网先同步附件再同步引用正文。
5. 上传旧版本过程中继续输入，返回成功不能误标新版本已同步。
6. 两台设备并改、MCP 与 UI 并改、远端删除而本地有草稿，均不静默丢内容。
7. 模拟写日志后崩溃、文件替换前后崩溃、上传成功响应丢失，恢复结果可解释且不盲目重复创建。
8. 文件名含中文、空格、括号，笔记移动和目录改名后标准 Markdown 图片及链接仍可用。
9. 一字 / 两字中文正文可搜；索引未完成明确标示，分页不混入其他库。
10. 删除单篇不删共享附件，目录软删除与恢复保留结构，重名恢复不覆盖。
11. 导入导出往返保留正文、层级与附件；缺失附件明确列出，不假报完整备份。
12. 禁止路径穿越、跨账号附件读取、预览脚本执行、任意 MCP 本地文件读取。
13. MCP 只读可用而写权限关闭时，全部写工具服务端拒绝；过期 revision 必须报冲突。
14. 退出桌面实例后 stdio 桥立即报告不可用，不弹窗启动桌面端。
15. 中英文切换不重载模块、不丢草稿；深浅主题、输入法、滚动及键盘操作通过真实交互验证。

16. A 修改上传后，B 在其他模块停留时仍自动发现并拉取新版；B 当前打开且干净的笔记自动更新，光标和滚动位置尽量保留。
17. 模拟丢通知、系统休眠、断网重连及增量 state 失效，补偿对账可恢复；仅修改时间不同不引发覆盖。
18. B 下载期间本地开始输入，提交时版本复核阻止覆盖；双方相同内容收敛，双方不同内容进入差异页。
19. 对比页区分远端实时与离线缓存；采用任一版本前保留恢复副本；解决冲突期间第三台设备更新仍触发条件写冲突。
20. AI 助手始终固定在设置按钮上方，窗口缩放不混入顶部业务区；关闭笔记不改变其他快捷键含义。

验证命令沿用项目：在 `desktop/frontend/` 执行 `pnpm test:i18n`、`pnpm test:notes-sync`、`pnpm lint`、`pnpm build`（预先生成 Wails 绑定）；在 `desktop/` 执行新增 notes / store / syncer 测试及 `go test ./internal/mcpbridge`。完整构建和跨平台交互未做时单独标记，不能用静态检查替代。

笔记工作区的网络同步状态与本地操作锁分开：首次绑定 Notes 后后台同步，不等待整库下载才允许打开已有本地笔记；手动同步先保存当前草稿，再发起网络同步，期间仍可选择及编辑本地笔记。同步按钮单独显示转动状态并合并重复请求，失败后恢复可重试状态并提示错误。`test:notes-sync` 用可控的未完成网络请求覆盖首次进入、手动同步中打开笔记、同步失败及本地保存失败后的恢复，不代替桌面端真实交互验收。

性能建议验收数据集为 5000 篇中小型笔记和混合附件：目录不一次渲染全部节点，后台下载受限并发；在明确的基准设备上记录冷启动、编辑输入和搜索耗时，完成基线后再确定硬性 SLA，不以未经测试的数字承诺效果。
